## Eval and message_text inventory (Task 5)

All 67 reachable `eval()` call sites outside the installer follow one pattern: `eval($code['code_text'])` over rows of `fanfiction_codeblocks` selected by a fixed hook type (`sitestats`, `storyblock`, `storyindex`, `storyend`, `printstory`, `storyblock-listing`, `login`, `search`, `categories`, `recent`, `authorpage`, and module hooks). Writers of that table are the installer's defaults, module installation through the admin area (code text comes from module files on disk, not from request input), and the admin. No author, member, or visitor path writes `fanfiction_codeblocks`. The hooks therefore classify as admin-controlled code, equivalent to "install a module", and were not rewritten; a future hardening pass could require an explicit allowlist setting.

Writers of `fanfiction_messages.message_text`: install/install.php step 7 (behind the owner secret and CSRF gate), admin/custpages.php and admin/messages.php (now token-gated, items 22 and 23), and install/upgrade11.php / install/upgrade20.php (disabled entirely, item 24). No other code path writes message text; viewpage.php renders it without executing (item 22).

Security defects (viewstory.php access condition, viewpage.php eval, CSRF in admin/custpages.php and admin/messages.php) are tracked in the Task 5 section below once confirmed with tests.

### Still open (need a decision or exceed the contract)

- ~~**Password hashing**: passwords are unsalted MD5.~~ **Resolved in v3.5.5-maint.2** (items 57-60 below): the password column widens to `varchar(255)` (idempotent, lazily applied at the first password write, offered on update.php, scriptable via `install/upgrade_modern_passwords.sql`), every hash write uses `password_hash()` (bcrypt), and legacy MD5 rows upgrade transparently at the next successful login. Hosts that deny the ALTER stay in working MD5 mode — never a truncated hash. The approach follows the official eFiction 3.5.7 release (efiction.org), GPL v2.
- **TinyMCE 3.0.9 (2008)**: known 3.x advisories around advimage/media URL handling. A vendored upgrade is a file replacement plus integration rework; the server-side strip_tags/descript pass on story text is the effective control. The descript widening (item 48) narrows what stored markup can do.
- **0777 story directories** (stories.php:255 and image dirs): deliberate shared-host compatibility (PHP often runs as a different user than the FTP owner there); tightening to 0755 would break writes on exactly the hosts this fork targets. Left as upstream behavior; hosts with a proper PHP-user setup can chmod down.
